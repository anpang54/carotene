## Carotene source code

File structure:
- `main.cpp` - The command-line interface
- `core/` - The core
  - `common.hpp` - Includes and helper functions
  - `scanner.hpp` - The scanner, turns source code into tokens
  - `compiler.hpp` - The compiler, turns those tokens into bytecode
  - `vm.hpp` - The virtual machine, runs that bytecode
  - `chunk.hpp` - Bytecode format and functions
  - `serialize.hpp` - Bytecode serialization
  - `value.hpp` - Types and normal objects
  - `object.hpp` - Heap-allocated objects
  - `format.hpp` - Formatting for `f""` strings
  - `licenses.hpp` - License text for `caro -l` (generated by `build.caro`)
- `stdlib/` - The standard library
  - `modules/` - Modules' functions, classes, and constants
    - `main.hpp` - The stuff that don't have a module
    - `x.hpp` - The stuff in module `x`
  - `methods/` - Methods on builtin types
    - `x.hpp` - The methods on builtin type `x`
  - `util/` - Utility stuff only used by the standard library
    - `natives.hpp` - Parameter checking and helper macros
    - `gui.hpp` - Rendering GUIs
    - `gui-styles.css` - CSS styles for GUI on web
    - `gui-styles.hpp` - Those CSS styles in a raw string (generated by `build.caro`)
    - `http.hpp` - HTTP(S) requests

Why is everything one translation unit? Because I don't like having to have separate `.cpp` and `.hpp` files for literally everything.
